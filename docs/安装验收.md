## 安装中的网络适配与限制

原安装脚本在模型下载时遇到代理 Fake-IP：下载域名被解析为 198.18.x.x，Ollama 的重定向保护拒绝访问。临时使用真实公网地址后又遇连接 EOF；后续镜像联网复核也曾遇 Docker Hub EOF。

最终使用 HTTPS 从同一官方 Ollama 仓库下载清单和所有 blob，支持断点续传，逐项核对大小和 SHA-256 后放入本项目新模型目录，再使用已经下载的固定镜像完成本地推理验收。没有关闭 TLS 或 Ollama 安全检查，没有修改全局代理。原始安装脚本的联网部分没有获得一次完整的成功退出；本机安装由上述补齐步骤和实际运行检查验收。日常启动使用现有镜像和模型，不需要重新安装；以后重新拉取镜像或新模型仍依赖网络条件。

## 使用

DSH 面板使用 `3099`，避开原独立 DSH 的 `3080`。SnowLuma 管理页 `5099`，QQ 扫码桌面 `6081`，均发布到本机回环地址。OneBot 和本项目 Ollama 仅在容器网络内部访问。

```bash
cd /home/example/dafeiyu-linux
bash start.sh
bash logs.sh dsh
```

在 DSH 页面登录模型账号或配置新的模型凭据；此安装不复用旧登录。`bge-m3` 用于记忆向量化，对话仍需模型服务。

随后手动启动 QQ：

```bash
bash start-qq.sh
bash status.sh
```

首次使用需本人在 SnowLuma 页面确认协议、完成管理认证，并在 noVNC 中登录机器人 QQ，必要时加载 QQ Hook。最后从主人 QQ 发真实私聊，确认回复、文件和记忆功能。

停止本项目：

```bash
bash stop.sh
```

容器未设置自动重启。项目数据映射到宿主机 `state/` 和 `vault/`；容器内普通用户 UID/GID 为 1000，与 example 对应。Docker 命令需要本机管理员认证，未将 example 加入 docker 组。
