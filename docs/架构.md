# 架构与模块运行说明

这份文档回答两件事：**它由什么组成**、**每个模块是怎么跑起来的**。
想直接装起来用，看 [README](../README.md)；想改代码，看 [运行说明](运行说明.md) 里的踩坑记录。

---

## 1. 全景

```
        主人（QQ 私聊 / 群聊）                      主人（浏览器）
                │                                        │
      Linux QQ + SnowLuma（OneBot 实现）               Web GUI :3080
                │  OneBot 11（反向 WS + HTTP）            │
                ▼                                        ▼
      ┌───────────────────────  dsh-napcat-bridge  ───────────────────────┐
      │  收：OneBot 事件 → DSH 消息     发：文本/图片 → OneBot 动作         │
      │  出网前清洗（去 <acp> 标记）· 长行分段（80 字）· 进度心跳            │
      └──────────────────────────────────┬────────────────────────────────┘
                                         ▼
      ┌──────────────────── DeepSeek Harness（宿主，profile=web）──────────┐
      │  agent loop：建 turn → pre-step 钩子 → 组装系统提示词 → 调模型       │
      │            → 工具调用循环 → 出网 → turn/end                        │
      │  会话存储 · 权限（sandbox/approval）· 工具注册表 · 插件装配          │
      └───┬───────────────┬───────────────┬───────────────┬───────────────┘
          │               │               │               │
   companion-core    dafeiyu-mind    dafeiyu-vault   能力插件（生图 / 管理 / 开关 / 梗库 …）
   人格·记忆·召回     心智层·注入      文件·表情包              │
          │               │               │                   │
          ▼               ▼               ▼                   ▼
   ~/.dsh/companion   mind.db         大肥鱼小窝/        ~/.dsh/image-studio
```

**QQ 协议端用的是什么**：本机跑的是 **SnowLuma**——它是注入官方 Linux QQ 客户端的 OneBot 11 实现，
并不是 NapCat。两者对上层是同一套协议，所以桥接插件仍叫 `dsh-napcat-bridge`（历史名字），换 NapCat 也能用。
接线方向是**反向 WS**：

| 端 | 谁监听 | 地址 | 说明 |
| --- | --- | --- | --- |
| SnowLuma HTTP 服务 | SnowLuma | `127.0.0.1:3000` | 内部调试与探活（`app/qq-status.py` 用它查在线） |
| SnowLuma WS 客户端 | SnowLuma 主动连 | `ws://127.0.0.1:6199/ws` | Universal 角色，断线 3 秒重连 |
| 桥接插件 WS 服务 | `dsh-napcat-bridge` | `127.0.0.1:6199` | 校验 `ws_reverse_token`，收事件、发动作 |

token 与端口都在 profile 补丁的 `napcat-bridge` 行里，SnowLuma 那份在
`native/snowluma/config/onebot_<机器人QQ>.json`。

其它外部可选服务：ComfyUI `127.0.0.1:8188`（生图）、Ollama `127.0.0.1:11434`（表情包向量）、
`bili-whale` CLI（B 站取稿/看片，需要登录 cookie）。

## 2. 分层职责

| 层 | 组件 | 职责 | 代码位置 |
| --- | --- | --- | --- |
| 宿主 | DSH `0.2.1-rc.3` | agent loop、会话、工具、权限、Web GUI | 独立安装（`~/.local/share/deepseek-harness`） |
| 通道 | `dsh-napcat-bridge` | QQ ↔ DSH 的收发、分段、心跳、清洗 | `plugins/dsh-napcat-bridge`（打了补丁） |
| 人格 | `dsh-companion-core` + `persona.md` | 人格注入、长期记忆、召回、日记、归档 | `plugins/dsh-companion-core`（打了补丁）+ `~/.dsh/companion/persona/persona.md` |
| 心智 | `dsh-dafeiyu-mind` | 精力/心情/日程/梦/记事/读稿/未结/主动消息 | `plugins/dsh-dafeiyu-mind` |
| 能力 | vault / image-studio / qq-tools / plugins / memewiki / remember-you | 文件与表情、生图、管理命令、插件开关、梗库、记忆界面 | `plugins/*` |
| 数据 | `~/.dsh`、`mind.db`、`大肥鱼小窝/` | 会话、配置、记忆库、她的文件 | 见第 5 节 |

**一条原则**：插件之间不互相 import，只通过「DSH 工具 + 注入段 + 事件」通信。
`mind` 要读心情，走的是 `~/.dsh/dsh-mood.json` 这个文件（mood 插件的唯一真相源），不是调 mood 的代码。

## 3. 一条消息从进来到出去

1. **进来**：QQ 消息 → NapCat → OneBot 事件 → bridge 转成 DSH 消息，同时广播 `napcat/message` 事件。
2. **建 turn**：宿主建会话轮次。`pre-step` 钩子依次跑：
   - `dafeiyu-qq-tools` 的权限纠正（把 QQ 会话固定成 `danger-full-access` + `never`，否则每条命令都卡在没人点的审批框上）；
   - 宿主自带的归档闸门（会话若在 `archivedSessionIds` 里，这一步直接 reject，模型一次都调不到）。
3. **组装提示词**：`system-prompt/assemble` 钩子上，各插件按顺序 push 自己的段：
   `dafeiyu:self`（SELF.md ≤1200 字）→ `dafeiyu:life`（此刻在做什么/穿什么）→
   `dafeiyu:agenda`（今天的安排）→ `dafeiyu:mind`（心情、未结事项、记忆提示）→
   `dafeiyu:breathe`（同一工具同参数打转时才出现）。
4. **模型 + 工具**：模型返回工具调用 → 宿主执行 → 结果回灌，循环到出文本。每步都会再走一次 `pre-step`。
5. **出去**：文本进 bridge → `sanitizeOutbound` 去掉内部标记 → `splitLongLine` 按 80 字切段 →
   OneBot 发送 → 广播 `napcat/sent`。
6. **收尾**：`turn/end` 后 mind 记账（她说了什么、有没有答应事、要不要记一条未结）。

## 4. 各模块怎么跑

### 4.1 `dsh-dafeiyu-mind`（心智层，核心）

**入口**：`lib/index.js` 的 `apply(ctx)`。挂载时做四件事：

1. **注册 16 个工具**：`mind_status` `mind_day` `mind_dream` `mind_event` `mind_sleep`
   `mind_read` `mind_watch` `mind_journal` `mind_self` `mind_soul` `mind_speak`
   `mind_budget` `mind_share` `mind_bond` `mind_open` `mind_life`。
2. **挂 4 段注入**：见上一节第 3 步（`ctx.on('system-prompt/assemble')`）。
3. **开 4 个定时器**（全插件唯一时钟，默认 tick 60s）：
   | 定时器 | 周期 | 干什么 |
   | --- | --- | --- |
   | `tick` | 60s | 推进精力/心情曲线、日程状态、到点提醒 |
   | `proactiveTick` | 120s | 判断"现在要不要主动开口"，走 `lib/speak/proactive.js` 的候选生命周期 |
   | `feedTick` | 600s | 夜间取稿（B 站），受每日预算限制 |
   | `planTick` | 300s | 到点排明天的日程（22:00 前后），失败退模板 |
4. **听 3 个事件**：`napcat/message`（记她说没说话）、`napcat/sent`（记已发）、`agent/created`（给新 agent 装备工具）。

**内部结构**（按职责分目录，纯函数优先，方便直接跑测试）：

| 文件 | 干什么 |
| --- | --- |
| `lib/body/engine.js` | 精力/心情状态机（纯函数，不碰 IO） |
| `lib/body/agenda.js` | 一天怎么过：日程、节目单、梦 |
| `lib/body/planner.js` / `planner-llm.js` | 日程的形状与规则 / 叫模型生成、解析、兜底 |
| `lib/body/plan-inject.js` | 把日程压成一段人话塞进提示词 |
| `lib/body/mood-bridge.js` | 读 `~/.dsh/dsh-mood.json`，不自己维护第二套心情 |
| `lib/body/wardrobe.js` | 从 image-studio 参考库读服饰/场景名，供日程用 |
| `lib/core/db.js` | `mind.db`：一个库、一条时间线 |
| `lib/core/gate.js` | 唯一的发言闸门（要不要现在找他） |
| `lib/core/budget.js` | 每日预算：B 站请求 / 精读篇数 / 取稿 token |
| `lib/feed/bili.js` | 取稿：调 vendor 里的 `bili-whale` CLI，字幕优先 |
| `lib/feed/watch.js` | 真"看"一整集：画面按变化去重 + 台词建时间码 + 两路对齐 |
| `lib/mind/*.js` | 手账、自我认识、SELF.md、换气、关系刻度 |
| `lib/speak/proactive.js` | 主动消息的候选生命周期（先想清楚为什么找他） |

**数据**：`大肥鱼小窝/04工作区/心智/mind.db`，表：
`meta`（键值）· `events`（心情事件）· `days`（每天日程/剧集/梦/日记）· `readings`（读过的稿）·
`journals`（手账）· `self`（自我认识）· `speak`（主动消息决策记录）· `loops`（未结事项）·
`breathe`（打转检测）· `usage`（每日用量）· `umos`（她的东西）。

**退化行为**：模型排日程失败 → 用模板；没 ComfyUI → 不生成图；没 B 站 cookie → 不取稿；数据库打不开 → 插件整体跳过，不影响聊天。

### 4.2 `dsh-dafeiyu-vault`（文件小窝 + 表情包）

**工具 8 个**：`vault_files` `vault_send_file` `vault_save_images` `meme_catalog` `meme_search` `meme_send` `meme_collect` `meme_send_image`。

**表情检索三段式**（`lib/meme-ranking.js`）：
1. `手工归类.json` 最高优先（人定的覆盖一切）；
2. 语义向量：`语义向量.json` 是 bge-m3 的 521×1024 向量，`score = (cos - 0.35) * 18`；
3. 关键词兜底：命中标签/类别名。

**去重**：先躲本会话最近 8 次发过的，再躲全局 3 次；在「最高分往下 2 分」的池子里随机，避免永远同一张。
**点名类别**（`category` 参数）且该类 0 张时直接返回空，不拿别的情绪凑。

**文件规则**：`01收件箱` 原件 → `02资料库/<类型>/<年-月>` → `03任务输出/<日期>` → `04工作区` 项目 →
`05临时` → `06归档`。写长内容先落盘再回话，不刷屏。

### 4.3 `dsh-dafeiyu-qq-tools`（管理员 + QQ 社交）

- `admin_sh` / `admin_sudo`：在整机执行命令。先试免密 `sudo -n`，不行再读 `~/.dsh/secrets/sudo.pass`（600）。
  单条命令 120s 超时、输出上限 12KB，全部记到 `04工作区/管理员日志.jsonl`。
- QQ 社交：`qq_signature` `qq_profile` `qzone_post` `qzone_delete` `qq_group_card`。
- **会话权限自纠正**：`wantOf(sessionId)` 决定这个会话该有的权限，监听 `session/event` 随时改回去
  （`enforcing` 标志防递归）。这是为了让 QQ 端不弹审批框——那边没人点。

### 4.4 `dsh-image-studio`（生图）

上游 v0.5.0 的本地改动版（见 `NOTICE.md`），加了一个 **ComfyUI provider**：

- `lib/providers-comfy.js`：把参考图逐张上传到 ComfyUI，挂到工作流的 `images.image_1..N`；
  单张参考按 cover 裁切；ComfyUI 没起时调 `tools/comfy-start.sh` 自动拉起。
- `lib/compose.js`：把「情境 / 神态 / 动作 / 镜头 / 光线 + 参考库条目」拼成最终提示词。
  **画风分两套**：`compose.stylePrompt`（生活图：半写实梦幻二次元）与 `compose.styleSticker`
  （表情贴纸：Q 版、粗黑描边、白底、可带中文气泡）；`image_generate` 用 `style: 'life' | 'sticker'` 选。
- 参考库 `~/.dsh/image-studio/library/{characters,outfits,scenes,props}`，每个条目一个文件夹 + `entry.json`（封面、别名、默认服饰）。
- 产物落 `~/.dsh/image-studio/outputs/<年-月>/img-*.png`，历史在 `history.jsonl`。

### 4.5 `dsh-mood`（心情与设置页）

- **状态机**：33 种心情，存在 `~/.dsh/dsh-mood.json`。周期判定 3–6 小时一次（随机间隔），
  会话事件小幅加减分，攒够余量（默认 5 分）且距上次切换 >15 分钟才真的换。
- **注入**：每轮注入当前心情名与行为倾向，**故意不写分值**——分数字段一变，上游 prompt 缓存就整段失效。
- **设置页**（浏览器侧 `client.js`）：人设、心情日记、硬盘记忆三页，数据走宿主 HTTP 前缀路由。

### 4.6 `dsh-companion-core`（人格与记忆，打补丁）

上游 0.17.1 + 本地补丁：
- 记忆召回加了**半衰地板**（`importanceFloor 0.12`、`floorRelevance 0.6`），避免老记忆被衰减到永不出现；
- 注入里加年龄提示与"别把猜测当事实"的约束；
- 人格从 `~/.dsh/companion/persona/persona.md` 读，**每轮读、改完即生效**，不用重启。

### 4.7 `dsh-napcat-bridge`（QQ 通道，打补丁）

上游 0.20.4 + 本地补丁。**插件名里的 "napcat" 只是历史**：它实现的是 OneBot 11，
本机对接的协议端是 SnowLuma（见第 1 节表格），换 NapCat 只需把对端配置指到同一个 `6199/ws`。
- `sanitizeOutbound`：出网前清掉 `<acp …>` 这类内部标记，别让主人看见；
- `splitLongLine`：单行超长按 80 字切段（QQ 端阅读体验）；
- **进度心跳**：长任务时每 6 秒起提示、20 秒内不重复、每轮最多 4 条、10 秒无进展也报一次；
- 断线重连与 OneBot 状态探测。

### 4.8 其余插件

| 插件 | 跑什么 |
| --- | --- |
| `dsh-dafeiyu-plugins` | `plugins_list` / `plugins_switch`：运行时启停插件省提示词；核心插件在禁止名单里 |
| `dsh-memewiki` | `search_meme_wiki`：本地 6668 条梗库（SQLite），毫秒级查词；`memewiki:prefetch` 预热 |
| `dsh-bili-whale` | B 站登录/体检与 CLI（`mind` 的取稿和看片都调它）；未登录时只是不工作，不影响别的 |
| `dsh-remember-you` | `memory_explain`：解释一条记忆是怎么被想起来的；带一个记忆管理网页 |
| `dsh-dafeiyu-runtime` | 工具超时兜底（默认 120s）、健康快照、QQ 端取消不收敛时强制收尾 |
| `dsh-dafeiyu-life` | 旧版"生活"插件，已被 `mind` 取代，留作参考，默认不启用 |

## 6. 启动与健康检查

**顺序**：宿主进程 → 加载 profile 补丁（插件装配）→ 各插件 `apply()` → bridge 连 OneBot → 可用。

判断"起来了"看两行日志：

```
[dafeiyu-mind] tools equipped: 16
[napcat-bridge] onebot connected
```

**安全重启**：`bash tools/restart-check-life.sh [延迟秒]`
它用 `systemd-run` 把重启动作从当前会话里摘出去，然后 stop → 等 3080 端口空 → start →
等日志出现 `[dafeiyu-*] tools ready`，最多重试 3 次，结果写 `/tmp/dsh-restart-report.log`。
**别直接 `systemctl restart`**——会让宿主进崩溃循环（踩过 45 分钟）。

## 7. 想加东西时改哪里

| 想加 | 改哪 |
| --- | --- |
| 一个新工具 | 插件里 `register({ name, description, parameters, async execute })`，参数用 JSON Schema |
| 一段每轮注入 | 监听 `system-prompt/assemble`，往 `assembly.sections` push `{ name, text, interpolate: false }` |
| 一个设置页 | 客户端 `ctx.slots.register({ name: 'settings.section', id, order, label }, Component)` |
| 一个新插件 | 放进 `plugins/`，`node_modules/<name>` 软链过去，profile `package.json` 登记，补丁里 **`- insert:`** |
| 改画风 | `~/.dsh/image-studio/config.json` 的 `compose.stylePrompt` / `compose.styleSticker` |
| 改人格 | `~/.dsh/companion/persona/persona.md`，保存即生效 |

**装第三方插件的规矩**：先复制进 `plugins/`，再软链到 `node_modules/`，最后改 profile 补丁。
直接 `npm i` 装会被下次重装冲掉你打的补丁。
